# Segurança e divulgação de vulnerabilidades

**O projeto é base de desenvolvimento e não está pronto para dados reais.** Antes de divulgar uma vulnerabilidade sensível, evite publicar provas de exploração com dados financeiros em issue público. Use o recurso **private vulnerability reporting** do GitHub, se estiver habilitado no repositório, ou contato de segurança informado pelo mantenedor quando disponibilizado.

Escopo de atenção: controle de acesso por workspace/perfil, recuperação de senha, XSS/CSRF, injeção de CSV/PDF, arquivos maliciosos, vazamento de backups/logs, idempotência e corridas de saldo.

Nunca envie `.env`, dumps PostgreSQL, extratos bancários ou códigos de recuperação em Issues.
